### 0.2 迁移号现状（硬约束）

`internal/db/sqlite.go` 中 `schemaVersion = 3`，迁移链为 **1 → 2（`archive_path`）→ 3（`toc_html`）**，均已落地。新增迁移项必须从 **4** 开始；若再把号记为 2 或 3，`migrate()` 的 `current >= schemaVersion` 会直接跳过，列永远不会被加上。

### 0.3 实际上线链路

`push main` → GitHub Actions（`tailscale/github-action` 加入 headscale + `ssh-agent`）→ SSH 到 `ser7` 执行 `homelab_blog_push_deploy.sh <version> <sha>` → 使用镜像 `100.64.0.4:5000/homelab-blog:latest`，`ports` 只绑定 `100.64.0.1:5200`（Tailscale 地址，不对公网开放）。

### 0.4 已知代码风险与设计取舍（另立任务修，不在文档中掩盖）

1. **`GET /projects/{id}/download` 公开下载＝设计决策，不是缺陷。** 作品集要求匿名访客点开即可拿到源码，因此该路由**刻意不挂鉴权**。隐私边界靠**发布者自我约束**：手动打包时排除 `.env`、`.git/`、私钥、tailnet 等隐藏/敏感文件。此条保留仅为提醒"发布前自查"，不是待修风险；代码侧配套加固与自查清单见 §12.11。
2. 公共导航 `partials.html` 对匿名用户无条件渲染 `/admin` 图标，与"后台入口不泄露"红线矛盾（`/about` 页已按登录态隐藏入口，导航没有）。
3. `GET /static/` 未禁目录列举。
4. `POST /admin/posts`、`POST /about/edit` 未设置 body 上限；只有预览接口限制了 512 KiB。
5. 创建 / 更新项目时各有一份几乎相同的上传代码（约 100 行 × 2），应抽成一个函数。

## 1. 项目概述

### 1.1 目标

用 **Go 原生标准库** 从零重写个人技术博客，替代现有 AI 辅助生成的 FastAPI 版本。

**核心动机**：现有博客仅实现了 GET 展示能力，缺乏对以下概念的完整认知：

- HTTP 方法语义（POST / PUT / DELETE 的状态变更能力）
- 请求-响应完整生命周期
- Markdown 解析（字符串到结构化的转换）
- 数据库状态管理与并发控制
- Go 工程化的项目组织方式

**本次重构以「完全理解每一行代码」为最高验收标准**，功能数量让位于代码可维护性。

### 1.2 系统组成

| 板块 | 说明 | 状态 |
| :--- | :--- | :--- |
| **文章（posts）** | 技术博客正文，支持 Markdown 写作、草稿与发布 | 已实现 |
| **项目库（projects）** | 作品集卡片墙，展示 GitHub 仓库与在线演示地址，可附 ZIP 源码包 | 已实现（附件为 v2.1 补充） |
| **关于（profile）** | 站主简介，单行记录，登录后可编辑 | 已实现（v2.1 补充） |
| **幕布（dashboard）** | `/` 的第一屏动效入口，通往 `/posts` | 已实现（v2.1 补充） |

### 1.3 单用户前提（架构的根本依据）

本系统为**单作者、单管理员**的个人博客。所有数据模型、并发策略、鉴权复杂度均以此为前提做最简化设计，**不做多租户预留**。

这个前提决定了：

- 选 SQLite 而非 MySQL（不存在并发写压力）
- 单一 admin 账号（无需角色权限系统）
- 不做分页（内容量 < 100）
- 不做全文搜索（数据量不足以产生检索需求）
- 不引入 CSRF Token（SameSite=Lax 已覆盖主要攻击面）

- [x] Docker 容器启动后自动建库建表，零人工干预（**管理员账号需执行一次 `cmd/admin-seed`，见 10.8**）

## 2. 技术选型与硬性约束

### 2.1 技术栈总表

| 维度 | 选型 | 说明 |
| :--- | :--- | :--- |
| 语言 | Go **1.25** | `go.mod` 声明 `go 1.25.0`；`crypto/pbkdf2` 自 1.24 起进入标准库 |
| HTTP | net/http + Go 1.22+ ServeMux | 原生支持按 HTTP 方法 + 通配路径注册路由 |
| 模板 | html/template | 服务端渲染（SSR） |
| 数据库 | SQLite（WAL 模式） | 嵌入式，零独立进程，零额外容器 |
| 驱动 | database/sql + `github.com/glebarez/go-sqlite` | **全项目唯一的第三方依赖**（纯 Go，无 CGO）。DSN 只认 `_pragma` / `_time_format` / `_txlock`，见 8.2 |
| 密码派生 | crypto/pbkdf2 | 标准库内置，OWASP 推荐 |
| 安全比较 | crypto/subtle | 常量时间比较，防时序攻击 |
| Markdown | **自研解析器**（纯标准库） | 不引入任何第三方 MD 库 |
| 代码高亮 | 前端 highlight.js | 后端只输出 pre/code 标签。**未接入**：`web/static/` 下没有 `vendor/`，见 §13.5 |
| 容器 | Docker 多阶段构建 | 非 root 用户运行 |
| 安全响应头 | 自建中间件（net/http） | nosniff / X-Frame-Options / CSP，见 10.7 |
| 可观测性 | `/healthz` + 零散 `log.Printf` | 探针不查库，见 10.10；**统一访问日志中间件未实现** |

### 2.2 明确排除的第三方依赖

| 依赖 | 排除理由 |
| :--- | :--- |
| Gin / Echo / Chi | 路由框架；Go 1.22+ 原生 ServeMux 已够用 |
| GORM | ORM；掩盖 SQL 与连接管理细节 |
| goldmark / blackfriday | MD 解析库；自研是本项目的核心学习目标 |
| golang.org/x/crypto/bcrypt | 已被标准库 crypto/pbkdf2 替代 |
| 任何前端框架（React/Vue） | SSR 网页三件套对本项目足够 |
| GitHub API 客户端库 | 本项目不调用 GitHub API（见 12.2） |
| CSRF Token 库 | SameSite=Lax 已覆盖主要攻击面 |

### 2.3 环境要求

- Go ≥ 1.25（`go.mod` 已声明 `go 1.25.0`）
- 可选：SQLite 命令行工具（用于手动排查数据）

| # | 原则 | 说明 |

```text
                          └────────┴──────────┴─────────┘
                                      │
                                    server
                          ┌───────────┼───────────┬──────────┐
                          ▼           ▼           ▼          ▼
                       config   markdown   posts/projects  web
                                    │       profile/auth   (embed FS)
                                    ▼
                                 仅标准库
```

> 单向依赖：`server` 只向下依赖领域包；领域包**不认识** `server` 与 `net/http`；`markdown` 与 `web` 是叶子。

### 4.2 允许的导入关系表

| 包 | 允许导入 | 对外暴露 |
| :--- | :--- | :--- |
| config | 无（叶子） | Config、Load() |
| markdown | 无（叶子） | Render(string) string |
| web | 无（叶子，仅 go:embed） | FS |
| db | config | Open(cfg) (*sql.DB, error)、NowUTC() |
| posts | config、*sql.DB | Store、Post、ErrNotFound、ErrDuplicate |
| projects | *sql.DB | Store、Project、ErrNotFound、ErrDuplicate |
| profile | *sql.DB | Store |
| auth | config、*sql.DB | Service、ErrInvalidCredentials |
| server | config、posts、projects、profile、auth、markdown、web | S（依赖结构体）、New(S) (*Server, error)、Start() error |
| app | 全部（它是装配者） | Run() error |

### 4.3 三条分层铁律

1. **领域包（posts / projects / auth）绝不导入 server**——它们不知道 HTTP 存在
2. **markdown 绝不导入任何项目内包**——它必须能被单独测试
3. **db 不包含任何业务概念**——它只负责连接与建表

### 4.4 关于拆包的尺子

| 条件 | 处理方式 |
| :--- | :--- |
| server/ 包 < 800 行 | **不拆**。平铺 + 按领域命名文件 |
| server/ 包 > 1500 行，或 handler 文件 > 12 个 | 拆成**兄弟包**：internal/server + internal/handlers（并列，不是嵌套） |
| 任何时候 | 不拆成父子嵌套包（父包要引用子包装配，子包要用父包设施，天然成环） |

**核心口诀**：**要拆就拆兄弟，不要拆父子。**

## 5. 核心设计模式：方法即 Handler

### 5.1 三阶段演进

| 方案 | 依赖获取方式 | 代价 |
| :--- | :--- | :--- |
| 全局变量 + 顶层函数 | 从全局变量拿 | 无法单元测试、无法多实例、任何包都能篡改 |
| 工厂函数 | 从闭包捕获 | 每个 Handler 配一个工厂函数 |
| **Server 方法值（本项目采用）** | 从接收者拿 | 依赖只声明一次、无工厂函数、Handler 可私有化；取舍理由见 ADR #12 |

### 5.2 底层机制：方法值（Method Value）

```text
func (s *Server) handlerIndex(w, r)      ← 方法定义
        ↓ 底层等价于
func handlerIndex(s *Server, w, r)       ← 接收者成为第一个参数
        ↓ 而 s.handlerIndex 就是
func(w, r) { handlerIndex(s, w, r) }     ← 闭包，s 已被固定
```

它的类型正是 func(http.ResponseWriter, *http.Request)，与 http.HandlerFunc 完全一致：

```go
var f func(http.ResponseWriter, *http.Request) = s.handlerIndex  // 合法
var h http.HandlerFunc = s.handlerIndex                          // 合法
```

### 5.3 路由表与 Handler 同包

路由注册集中在 `internal/server/routes.go` 的私有方法 `routes()`，与 Handler 定义在同一个包内，便于内聚维护。**完整路由表见第 7 章。** `GET /{$}` 收窄根路径、自定义 404 的必要性见 §7.1；中间件接入时的类型转换见 §5.4。

### 5.4 中间件接入的类型转换陷阱

| 方法 | 参数 | 传方法值 |
| :--- | :--- | :--- |
| mux.HandleFunc(pattern, f) | func(w, r) | 可直接传 |
| mux.Handle(pattern, h) | http.Handler 接口 | 需 `http.HandlerFunc(...)` 包装 |

```go
mux.Handle("GET /admin", s.requireAuthPage(http.HandlerFunc(s.handlerAdmin)))
```

> **口诀**：不加中间件用 HandleFunc；加了中间件用 Handle + http.HandlerFunc(...)。

### 5.5 三个易错点

| # | 易错点 | 正确做法 |
| :--- | :--- | :--- |
| 1 | 接收者用值而非指针 | 统一用 (s *Server) |
| 2 | 在 New() 填充字段前注册路由 | 先填完字段再注册，否则请求进来时才 panic |
| 3 | 在 Handler 里修改 s 的字段存请求状态 | s 跨请求共享；请求级状态走局部变量或 r.Context() |

### 5.6 组合根：app.Run()

**装配顺序**（`internal/app/app.go`，以下为**代码现状**）：

1. `cfg := config.Load()`
2. `os.MkdirAll(cfg.UploadsDir, 0o755)`：先确保附件目录存在，再开库
3. `db.Open(cfg)`：打开数据库，内含 schema 迁移与 PRAGMA 自检（见 8.2 / 8.3 / 8.7）
4. 依次构造 `auth.NewService(cfg, database)`、`posts.NewStore(cfg, database)`、`profile.NewStore(database)`、`projects.NewStore(database)`
5. 把这些依赖装进 `server.S` **结构体**（字段 `Cfg` / `AuthSvc` / `PostStore` / `Profile` / `Projects`），再 `server.New(s)` 返回 `*Server`；最后 `srv.Start()`
   - 注意实际签名是 `New(S) (*Server, error)` 与 `Start() error`，**没有 `Start(ctx)`**（补优雅关闭时才引入 ctx，见下方流程）

**启动与关闭流程**（`Start(ctx)` 内）——**以下 1–5 是目标写法，当前未实现**：

1. `errCh := make(chan error, 1)`
2. `go func() { errCh <- srv.ListenAndServe() }()`
3. `select` 等待：`ListenAndServe` 启动失败则直接返回该错误；否则等待 ctx 被取消
4. ctx 取消后，用 `cfg.ShutdownTimeout` 构造带超时的 context
5. 调用 `srv.Shutdown(ctx)`，等待在途请求收尾

> **现状**：`app.Run` 仍是直接 `ListenAndServe` + `log.Fatal` 型退出，没有 `signal.NotifyContext`、没有 `Shutdown`；`ShutdownTimeout` 只是预埋字段。补齐时用 `signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)` 生成 ctx 传入 `Start(ctx)`；Docker `stop` 发送 SIGTERM，不监听就只能硬杀（ADR #42 未落实）。

**职责边界**：
> app 决定「用哪些组件」；server 决定「这些组件挂在哪些路径上」。

### 5.7 main.go（保持极简）

main.go 只做一件事：调用 `app.Run()`，出错时走 `log.Fatalf("fatal: %v", err)`。它不包含任何装配逻辑。

### 6.2 防御纵深（Defense in Depth）

| 层级 | 手段 | 作用 | 现状 |
| :--- | :--- | :--- | :--- |
| 第一层（Nginx） | `location ^~ /admin` 路径 IP 白名单 | 公网请求在进入 Go 进程前就被 403 拒绝 | **未部署**，用 Tailscale 绑定替代 |
| 第二层（Go） | 双认证中间件 | 即使 Nginx 配置失误，仍是最后一道墙 | 已实现 |

### 6.3 数据流向

**写入路径（发布文章）**

```text
浏览器表单提交
  → POST /admin/posts
  → requireAuthPage 校验登录态（失败则 303 到登录页）
  → Handler 解析表单 (r.ParseForm)
  → markdown.Render(content_md) 生成正文 HTML 与 []Heading（铁律 4 的 scheme 白名单在解析器内完成）
  → markdown.RenderTOC(headings) 生成目录 HTML（标题少于 3 个时为空串）
  → postStore.Create()：写入 content_md / content_html / toc_html / render_version = cfg.ParserVersion
  → slug 冲突 → ErrDuplicate → 409（回填表单并保留已填内容）
  → 成功 → 303 重定向到文章详情页
```

> **更新路径同样要刷新 `render_version`**：`POST /admin/posts/{id}` 会重算 `content_html` 与 `toc_html`，
> 保存时必须一并写 `render_version = cfg.ParserVersion`（见 §8.6）。若只更新
> `content_md` / `updated_at` 而漏掉该列，`cmd/render-backfill` 会把已最新的行再重复处理一遍。

**读取路径（浏览文章）**

```text
浏览器请求 /post/{slug}
  → 公开 Handler（无鉴权）
  → postStore.GetBySlug()
  → 校验 status == "published"，否则返回 404
  → 直接把库中的 content_html 与 toc_html 注入模板
  → 返回完整 HTML 页面
```

**删除路径（fetch 调用）**

```text
JS: confirm() → fetch('/admin/posts/3', { method: 'DELETE' })
  → DELETE /admin/posts/{id}
  → requireAuthAPI 校验登录态
      ├─ 失败 → 401 JSON（JS 能识别，不会被重定向误导）
      └─ 通过 → Handler
  → 校验 {id} 为合法数字
  → postStore.Delete(id)
  → 成功 → 204 No Content
  → JS: location.reload()
```

### 7.3 删除操作采用 DELETE 方法

#### 服务端完全支持 DELETE

Go 1.22+ 的 ServeMux 路由模式格式为 `[METHOD ][HOST]/[PATH]`，GET / POST / PUT / DELETE / PATCH 全部可用：

```go
mux.Handle("DELETE /admin/posts/{id}", s.requireAuthAPI(http.HandlerFunc(s.handlerDeletePost)))
```

#### 唯一的限制在浏览器 HTML 表单这一层

HTML 规范规定 form 元素的 method 属性只有 get、post、dialog 三个合法值，**发不出 DELETE 请求**。因此本项目采用混合策略：

| 操作 | 客户端 | 服务端路由 |
| :--- | :--- | :--- |
| 创建 / 更新 | 普通表单（method="POST"） | POST /admin/posts、POST /admin/posts/{id} |
| **删除** | **fetch(url, {method:'DELETE'})** | **DELETE /admin/posts/{id}** |

由于本项目前端由 AI 生成，且后台已有 JS（预览功能），引入 fetch 不破坏架构一致性，同时获得严格的 RESTful 语义。

#### SQL 注入防线

`{id}` 来自 URL，属于**不可信输入**，必须使用预编译占位符：

```go
// 正确
db.Exec("DELETE FROM posts WHERE id = ?", id)

// 危险：字符串拼接会被 SQL 注入
db.Exec("DELETE FROM posts WHERE id = " + r.PathValue("id"))
```

### 7.4 删除接口的前后端交互契约

> 本节供前端生成时参照，确保 JS 与服务端约定一致。

#### 请求格式

```text
DELETE /admin/posts/{id}
Cookie: session=<hex>       （浏览器自动携带）
请求体: 无
```

#### 响应约定

| 状态码 | 含义 | JS 应如何处理 |
| :--- | :--- | :--- |
| 204 No Content | 删除成功 | location.reload() 刷新列表 |
| 400 Bad Request | id 非法（非数字） | alert('参数错误') |
| 401 Unauthorized | 未登录 / 会话过期 | location.href = '/admin/login' |
| 404 Not Found | 记录不存在（可能已被删） | 刷新列表即可 |
| 500 Internal Server Error | 服务器错误 | alert('删除失败，请重试') |

#### JS 侧执行顺序

```text
1. confirm('确定删除这条记录？')   → 用户取消则直接 return
2. fetch('/admin/posts/' + id, { method: 'DELETE' })
3. 根据 response.status 分支处理（见上表）
4. 任何情况下都不假设"请求发出去了就一定成功"
```

#### 服务端 Handler 骨架要点

```text
handlerDeletePost:
  1. 取 URL 中的 {id}，用 strconv.ParseInt 校验
  2. 解析失败 → 400
  3. 调用 postStore.Delete(id)
  4. errors.Is(err, posts.ErrNotFound) → 404
  5. 其他错误 → 500
  6. 成功 → w.WriteHeader(http.StatusNoContent)
```

> **注意**：204 响应不能带 body。写了 w.WriteHeader(204) 之后如果还调用 w.Write(...)，Go 会记录警告，部分客户端也会解析异常。

## 8. 数据模型

### 8.1 完整 Schema

```sql
-- 本文件只放 DDL。所有 PRAGMA 一律通过 DSN 的 _pragma 参数设置（见 8.2）。
-- 因为 foreign_keys / busy_timeout 是连接级、journal_mode 是数据库级，
-- 写在脚本里只在执行脚本的那一条连接上生效，语义混乱且容易被误认为全局生效。

-- ========== 文章表 ==========
CREATE TABLE IF NOT EXISTS posts (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    slug           TEXT     NOT NULL UNIQUE,      -- URL 标识，如 go-fd-leak
    title          TEXT     NOT NULL,
    summary        TEXT     DEFAULT '',           -- 摘要，列表页展示
    content_md     TEXT     NOT NULL,             -- Markdown 原文（事实源，供二次编辑与回填）
    content_html   TEXT     NOT NULL,             -- 渲染后 HTML（缓存，供直接展示）
    toc_html       TEXT     NOT NULL DEFAULT '',  -- 目录 HTML（与正文同源产出，空串=无目录）
    status         TEXT     NOT NULL DEFAULT 'draft',  -- 'draft' | 'published'
    created_at     DATETIME NOT NULL,             -- 由 Go 层生成，写入前一律 .UTC()
    updated_at     DATETIME NOT NULL,
    published_at   DATETIME,                      -- 仅 published 时非空
    render_version INTEGER  NOT NULL DEFAULT 0    -- content_html 由哪一版解析器渲染，见 8.6
);

CREATE INDEX IF NOT EXISTS idx_posts_list
    ON posts(status, published_at DESC);

-- ========== 项目库表 ==========
CREATE TABLE IF NOT EXISTS projects (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    slug         TEXT     NOT NULL UNIQUE,        -- 用于锚点定位
    title        TEXT     NOT NULL,
    summary      TEXT     NOT NULL,               -- 卡片上的一句话简介
    github_url   TEXT     NOT NULL,               -- [Source] 按钮目标
    demo_url     TEXT     DEFAULT '',             -- [Demo] 按钮目标（可空）
    archive_path TEXT     NOT NULL DEFAULT '',    -- ZIP 附件在 data/uploads/ 下的相对文件名（v2.1 补充）
    tech_stack   TEXT     DEFAULT '',             -- 形如 ",Go,Docker,SQLite,"
    cover_image  TEXT     DEFAULT '',             -- 封面图 URL（可空）
    status       TEXT     NOT NULL DEFAULT 'active',  -- 'active' | 'archived'
    featured     INTEGER  NOT NULL DEFAULT 0,     -- 置顶（1=置顶）
    sort_order   INTEGER  NOT NULL DEFAULT 0,     -- 手动排序权重
    created_at   DATETIME NOT NULL,
    updated_at   DATETIME NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_projects_order
    ON projects(featured DESC, sort_order ASC, created_at DESC);

-- ========== 管理员表 ==========
CREATE TABLE IF NOT EXISTS admins (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    username      TEXT NOT NULL UNIQUE,
    password_hash BLOB NOT NULL,      -- PBKDF2 派生密钥（原始字节）
    salt          BLOB NOT NULL,      -- 16 字节随机盐
    iterations    INTEGER NOT NULL,   -- 记录迭代次数，便于未来升级强度
    created_at    DATETIME NOT NULL
);

-- ========== 会话表 ==========
CREATE TABLE IF NOT EXISTS sessions (
    token      TEXT PRIMARY KEY,      -- 32 字节随机数的 hex 编码
    admin_id   INTEGER NOT NULL,
    expires_at DATETIME NOT NULL,
    created_at DATETIME NOT NULL,
    FOREIGN KEY (admin_id) REFERENCES admins(id) ON DELETE CASCADE
);

-- 过期会话清理按 expires_at 扫描，必须有索引，否则每次清理都全表扫描
CREATE INDEX IF NOT EXISTS idx_sessions_expires ON sessions(expires_at);

-- ========== 站主简介表（单行，v2.1 补充，见 §13.2 关于页） ==========
CREATE TABLE IF NOT EXISTS site_profile (
    id         INTEGER PRIMARY KEY CHECK (id = 1),  -- 全表恒定一行
    content_md TEXT    NOT NULL DEFAULT '',         -- Markdown 原文
    updated_at DATETIME NOT NULL
);
```

### 8.2 连接配置

★ DSN 只使用 glebarez/go-sqlite 认识的参数：`_pragma` / `_time_format` / `_txlock`。
驱动源码 `applyQueryParams` 只消费 `_pragma`（可重复出现），其余 query 参数被静默忽略、不报错。
若照抄 mattn 风格的 `_journal_mode=WAL&_foreign_keys=on`，程序照样启动，
但 PRAGMA 根本不会执行——WAL 没开、外键失效，且没有任何报错提示。

DSN 字符串形如：

```go
dsn := "file:" + cfg.DBPath +
    "?_pragma=journal_mode(WAL)" +
    "&_pragma=synchronous(NORMAL)" +
    "&_pragma=foreign_keys(1)" +
    "&_txlock=immediate"   // 写事务直接请求写锁，避免 deferred 升级时的 SQLITE_BUSY
```

连接池必须固定为串行化：`SetMaxOpenConns(1)` + `SetMaxIdleConns(1)` + `SetConnMaxLifetime(0)`
（不主动回收连接）。内容量 < 100，读并发没有收益，用串行换取零 SQLITE_BUSY（决策见 ADR #22）。

> ★ 由于只有一条连接，任何忘记 `rows.Close()` 的查询都会占死它，导致整站死锁——
> 因此 store 层「拿到 rows 立即 `defer rows.Close()`」是**硬约束，不是最佳实践**。

> **关于 `_time_format`**：本驱动把 `DATETIME` 列的默认写入格式固定为
> `2006-01-02 15:04:05.999999999-07:00`（即 SQLite 的 format 7），无需额外指定。
> 真正的要求是**写入前一律 `.UTC()`**：后缀恒为 `+00:00` 时，TEXT 排序才等价于时间排序（见 ADR #23）。

### 8.3 Pragma 的实际归宿

| Pragma | 驱动默认 | 本项目取值 | 设置方式 |
| :--- | :--- | :--- | :--- |
| journal_mode | delete | WAL | DSN `_pragma=journal_mode(WAL)`（数据库级，持久） |
| **foreign_keys** | **OFF** | **ON** | DSN `_pragma=foreign_keys(1)`（连接级） |
| synchronous | FULL | NORMAL | DSN `_pragma=synchronous(NORMAL)`（连接级） |
| busy_timeout | **5000** | 5000 | **驱动建连时已默认执行 `pragma BUSY_TIMEOUT(5000)`**，无需自己设 |

> **为什么 foreign_keys 默认关闭**：SQLite 在 3.6.19（2009）之前不支持外键。
> 若当时默认开启，会导致所有现存数据库瞬间报约束错误。为了向后兼容，它被设计成**需要显式开启**。
>
> **为什么 busy_timeout 不需要写**：`glebarez/go-sqlite` 建立每条连接时都会先执行一次
> `pragma BUSY_TIMEOUT(5000)`。不了解这点会导致误判——把它写进 mattn 风格的 DSN 后，
> 真正生效的 5000 来自驱动默认值，而不是你的配置。

**启动时必须验证实际值**（三项都要打印并断言，否则 DSN 拼错也没人发现）：
启动时读取并断言 `journal_mode = wal`、`foreign_keys = 1`、`synchronous = 1`，
**任一不符则 `return error` 中止启动**。

> 统一走 `return err`，不要在这里混用 `panic`——自检失败也是一条正常的启动错误路径，交给 `app.Run` 统一处理。

> 验收期望值：`journal_mode = wal`、`foreign_keys = 1`、`synchronous = 1`
> （synchronous：OFF=0，NORMAL=1，FULL=2）。这三个值是阶段一的硬性验收项，见 17.3。

### 8.4 哨兵错误约定

store.Delete() 必须区分「记录不存在」与「数据库错误」，否则 Handler 无法给出正确的状态码。

```go
// internal/posts/store.go
var (
    ErrNotFound  = errors.New("post not found")
    ErrDuplicate = errors.New("post slug already exists")   // slug 唯一约束冲突
)

// internal/projects/store.go
var (
    ErrNotFound  = errors.New("project not found")
    ErrDuplicate = errors.New("project slug already exists")
)
```

Handler 中用 `errors.Is` 分流：

| 判断 | 响应 |
| :--- | :--- |
| `errors.Is(err, X.ErrNotFound)` | 404 |
| `errors.Is(err, X.ErrDuplicate)` | 409 Conflict，提示「该 slug 已被占用，请换一个」 |
| 其余 | 500 |

> **为什么必须区分**：`slug` 有 `UNIQUE` 约束，重复插入时驱动返回的是约束错误。若统一按 500 处理，
> 用户看到的是「服务器错误」而非「slug 已存在」——这是最容易漏掉的错误路径之一。
> 建议在 store 层把驱动错误翻译成 `ErrDuplicate` 再向上返回，不要在 handler 里比对驱动错误字符串。

### 8.5 字段设计决策

| 决策 | 理由 |
| :--- | :--- |
| **posts 同时存 MD 原文与 HTML** | MD 用于二次编辑；HTML 用于直接展示，避免重复解析 |
| **projects 只存纯文本，无 HTML** | 项目介绍是一句话简介，无需 Markdown 渲染 |
| **没有 tags 表** | 本期范围裁剪；技术栈标签用逗号分隔字符串 |
| **不含 reading_time 字段** | 无实际价值，且有挂机作弊风险 |
| **AUTOINCREMENT 仅用于内部 id** | 对外一律使用 slug，不暴露自增 id（防遍历） |
| **时间由 Go 层生成，且一律 UTC** | 驱动把 `DATETIME` 列写成 `2006-01-02 15:04:05.999999999-07:00` 的 TEXT；只有全部为 UTC（后缀恒为 `+00:00`）时，TEXT 排序才等价于时间排序，见 ADR #23 |
| **iterations 单独存列** | 未来提高迭代强度时，旧密码仍可验证 |
| **projects 无 gh_ 前缀字段** | 不调用 GitHub API，见 12.2 |
| **posts 增加 render_version** | content_html / toc_html 是缓存，需记录生成它们的解析器版本以支持回填，见 8.6 |
| **projects 增加 archive_path** | 存 ZIP 附件的相对文件名（不含目录），文件落在 `data/uploads/`；空串表示无附件（v2.1 补充） |
| **site_profile 恒定一行** | 站主简介单作者单记录，`id INTEGER PRIMARY KEY CHECK (id = 1)` 把"只有一行"写进表结构（v2.1 补充） |
| **posts 增加 toc_html** | 目录由解析器同源产出、随正文一起入库，避免请求期二次扫描；空串表示不渲染目录（v2.2 已落地，见第 20 章） |

### 8.6 解析器升级后的 HTML 回填（命令已实现）

> 状态：`config.ParserVersion` **当前为 2**（TOC 落地后从 1 升上来），`cmd/render-backfill` **已实现**，支持 `-dry-run`。

`content_html` 是缓存，**事实源是 `content_md`**。解析器一旦修 bug，历史行里的旧 HTML 不会自动更新，
会出现「单元测试全绿、线上某篇仍错」的隐蔽问题。

- `config.Config` 维护 `ParserVersion`，每次改动解析逻辑就 +1。
- **创建与编辑保存**文章时：只要重算了 `content_html`（无论新建还是 `POST /admin/posts/{id}` 更新），
  都必须同步写入 `render_version = cfg.ParserVersion`。编辑只改 `content_md` 而漏写该列，
  回填命令会把已最新的行再重复处理一遍。
- `cmd/render-backfill`（已实现）：`ListAll()` 扫全表，逐行判断 `render_version >= cfg.ParserVersion` 则跳过；
  其余用 `content_md` 重新 `markdown.Render` + `markdown.RenderTOC`，只执行
  `UPDATE posts SET content_html = ?, toc_html = ?, render_version = ? WHERE id = ?`。
- `-dry-run`：只打印每篇的 `md=` / `toc=` 长度与待处理条数，不写库。正式执行前先跑一次预演。
- 任一步失败即中止，错误信息带 slug 上下文；因只处理落后版本的行，**可安全重跑（幂等）**。
- 该命令是独立 `main` 包，复用 `internal/db`、`internal/posts` 与 `internal/markdown`，**不启动 HTTP 服务**；
  镜像内不包含该二进制，需在能访问 `./data` 卷的机器上 `go run ./cmd/render-backfill`。
- ★ `toc_html` 与 `content_html` 来自同一次 `Render`，必须在同一条 INSERT / UPDATE 里写入，
  不允许「只刷正文不刷目录」（见 §20.4）。

### 8.7 Schema 迁移策略（必须先定，再改表）

**`CREATE TABLE IF NOT EXISTS` 不会给已存在的表加列，也不会补索引。** 只要有人已经跑出过一份
`blog.db`，你之后往 `schema.sql` 里新增的列（例如 v1.6 加入的 `render_version`）和索引
（`idx_sessions_expires`）**都不会生效**，随后 `SELECT render_version` 会直接报 `no such column`。

本项目采用**最小可用且幂等**的版本化迁移，不引入迁移框架。

#### 8.7.1 为什么必须幂等：存量库的版本基线不可信

`user_version` 是本项目新引入的概念。一个在 v1.6 schema 下创建、**已经含有 `render_version` 列**
但 `user_version` 仍为 0 的库，若按「`user_version < N` 就执行 `ALTER TABLE posts ADD COLUMN
render_version`」的朴素逻辑，会立刻报 `duplicate column name` 并中止启动。

因此**迁移的每一步都必须先探测再执行**。存量库的版本基线**以实际表结构为准**
（`PRAGMA table_info(<table>)`），而不是以 `user_version` 为准；`user_version` 只用来决定从哪一级开始尝试。

#### 8.7.2 迁移算法

1. 启动时读取 `PRAGMA user_version`（默认 0），仅用于**决定从哪一级开始推进**，不作为结构真值。
2. 定义迁移列表：每项是 `version` + 一段**幂等操作**。加列前先
   `PRAGMA table_info(posts)` 判断列是否已存在，缺失才 `ALTER TABLE ... ADD COLUMN`；
   建索引一律用 `CREATE INDEX IF NOT EXISTS`（本身幂等）。
3. 依次执行 `user_version < N` 的迁移；每步成功后在**同一事务内**把 `user_version` 提升到 N。
4. 全新库：执行 `schema.sql` 建表后，直接把 `user_version` 设为当前最高版本。
5. 全部迁移放在事务内；任一步失败则回滚并**中止启动**，绝不带着半迁移的库继续跑。

> **已落地迁移项（`user_version` 1 → 2 → 3，`schemaVersion = 3`）**：
> 1. `posts` 补 `render_version` 列（`table_info` 探测后 `ALTER TABLE`）；
> 2. `projects` 补 `archive_path` 列；
> 3. 补建 `idx_sessions_expires` 索引；
> 4. `posts` 补 `toc_html TEXT NOT NULL DEFAULT ''` 列（v2.2 落地）。
>
> ★ **3 号已被占用**。下一项迁移必须使用 `user_version` 3 → **4**，同时把 `schemaVersion`
> 常量改为 4。若继续沿用旧号，`current >= schemaVersion` 会直接跳过迁移，列永远不会出现。

#### 8.7.3 ★ `PRAGMA user_version = ?` 不能参数化

SQLite 不支持对 `PRAGMA` 语句使用占位符，`db.Exec("PRAGMA user_version = ?", v)` 不会报错，
但会被**静默忽略**，`user_version` 永远停在 0，迁移因此每次都当作全新库重跑。

```go
// 错误：占位符对 PRAGMA 无效，语句被静默忽略
db.Exec("PRAGMA user_version = ?", version)

// 正确：版本号来自编译期常量，用 fmt.Sprintf 格式化整数
db.Exec(fmt.Sprintf("PRAGMA user_version = %d", version))
```

★ **硬性规定**：允许进入这条 SQL 的**只能是 `const` 定义的迁移版本号整数**。
**绝不允许任何外部输入**（HTTP 参数 / 配置 / 环境变量 / 从数据库读出的值）参与拼接。
`version` 是编译期常量、不是运行时数据——这条线一旦模糊，就会养成字符串拼接的习惯并最终演变成注入。

> **开发期兜底**：若尚无任何生产数据，允许「删掉 `./data/blog.db*` 重建」，但这句话必须写死在
> Runbook 里，且**只对开发库成立**——不要让它变成上线后遇到加列时的默认动作。
> 生产/存量库的正确路径永远是「幂等迁移」，不是删库。

## 9. Markdown 解析器设计

> **本节是整个项目技术含量最高的部分。**

### 9.1 语法支持边界（标准集，已实现）

| 类别 | 支持的语法 |
| :--- | :--- |
| **块级** | ATX 标题（# 至 ######）、围栏代码块（三个反引号，可带语言标识）、引用（>）、无序列表（- * +）、有序列表（1.）、任务列表（- [ ] / - [x]）、表格（含对齐行）、水平线（---）、段落 |
| **行内** | 行内代码（单个反引号）、粗体（双星号）、链接（`[文本](http/https 地址)`） |
| **明确不支持** | **斜体（单星号）、图片（`![]()`）**、嵌套结构、原生 HTML 标签、脚注、数学公式、setext 标题 |
| **标题 id** | h2–h4 注入由内容派生的 `id`（转小写、保留 Unicode 字母数字、其余折叠为 `-`；空标题回退 `sec-N`，同名追加 `-2`），供 TOC 锚点使用；h1/h5/h6 不带 id（见 §20.2、§20.7） |

> **复杂度警告**：表格是标准集中唯一需要「预扫描整块」才能确定结构的语法。
> 它迫使解析器必须采用**两段式架构**。

### 9.2 两段式架构

```text
输入: string (Markdown 原文)
  │
  ├─ [0] 预处理：统一换行符 \r\n → \n（当前实现仅此一步，未剔除行尾空白）
  │
  ├─ [1] 块级扫描：按空行 / 围栏边界切分为块序列
  │
  ├─ [2] 块级渲染：按块类型分派
  │      ★ 代码块内部完全跳过行内解析
  │
  └─ [3] 行内解析：在段落 / 标题 / 列表项 / 表格单元格内执行
         ★ 单趟从左到右扫描，绝不做多趟正则替换

输出: string (HTML) + []Heading。对外签名 `func Render(src string) (string, []Heading)`，
      一次遍历同时产出正文与标题元数据，目录由 `markdown.RenderTOC(headings)` 渲染（见第 20 章）
```

### 9.3 四条不可违反的实现铁律

#### 铁律 1 — 行内解析必须单趟扫描

```text
错误做法：先全局替换粗体标记，再全局替换斜体标记

   危害：位于行内代码内的粗体标记会被误命中，破坏原意

正确做法：从左到右单趟扫描，每个字符只被消费一次

   遇到反引号  → 向右找配对，内部不解析 Markdown，但内容必须 html.EscapeString
   遇到双星号  → 向右找配对，递归处理夹层
   遇到方括号  → 尝试匹配链接
```

> **实现现状**：`inline.go` 用 `strings.Split` 按分隔符分段递归完成上述三类，功能等价但并非严格单趟扫描；
> 单个星号与叹号图片不在支持范围内（见 §9.1）。

#### 铁律 2 — 代码块只跳过 Markdown 解析，不豁免 HTML 转义

围栏代码块内部**不执行任何 Markdown 解析**：井号不是标题、星号不是粗体、方括号不是链接。
这是新手最常见的 bug 来源。

但「跳过 Markdown 解析」**不等于「原样写进 HTML」**。本铁律里的"原样"只成立于 Markdown 语义层，
**输出前仍必须做 `html.EscapeString`**（与铁律 3 是同一条防线，两条铁律不冲突：
铁律 2 管「不解析 Markdown」，铁律 3 管「写 HTML 前必须转义」）。

★ **反例（必须避免）**：若把代码块内容直接拼接输出，围栏内写入下面这行

    </code></pre><script>alert(document.cookie)</script>

会被原样写进 `content_html`；而 `content_html` 最终以 `template.HTML()` 注入模板（见 §6.3），
浏览器会把它当作真正的 `</pre>` + `<script>` 执行 → **存储型 XSS**。

正确做法：代码块在块级扫描阶段整块取出（不做行内解析），随后经 `html.EscapeString`，
再包进 `<pre><code>`。下面这段内容整体位于围栏代码块内部，其中的井号绝不能被当成 H1 标题：

```text
    #include <stdio.h>      ← 这个井号不是标题
    #define MAX 100         ← 转义后原样保留
```

#### 铁律 3 — 所有文本必须 HTML 转义

因为要用 template.HTML() 绕过模板自动转义，**解析器必须自己承担全部 XSS 防护责任**。
规则：**所有非标签文本（含围栏代码块与行内代码的内容）必须先 `html.EscapeString` 再拼接**。
行内代码与围栏代码块一视同仁：只豁免 Markdown 解析，**不豁免 HTML 转义**。

#### 铁律 4 — 链接 / 图片的 URL 必须做 scheme 白名单

**文本转义保护不了属性。** 链接与图片的 URL 落在 `href` / `src` 属性里，是另一条独立攻击面：

```text
[点我](javascript:alert(document.cookie))  → <a href="javascript:...">   可点击执行 → XSS
（图片语法 `![]()` 当前不支持，因此不存在 src 攻击面；将来支持图片时必须复用同一白名单）
```

规则（**当前实现**）：

- 只放行 `http://` / `https://` 两种前缀，其余一律降级为整行纯文本（不生成 `<a>`）。
- 因为只放行显式 scheme，`//evil.com`、`javascript:`、`data:`、`file:` 天然被拒绝。
- URL 仍需 `html.EscapeString` 后再写入属性，防止用引号闭合属性。
- ★ **已知局限**：站内相对路径（`/posts/x`）与 `#` 锚点也会被降级为纯文本。
  若要支持站内链接，需扩展白名单并保留"拒绝 `//` 与 `/\` 开头"的判断——这属于 TOC / 内链改造的一部分（见 §20）。
- 该逻辑位于 `inline.go` 的 `sanitizeURL`，与文本转义同趟完成。

### 9.4 单元测试策略（测试驱动开发）

> **状态：未落地。** 仓库内 `internal/markdown/*_test.go` 数量为 0。以下清单是待补的测试基线，
> 也是第 17 章验收的前提。

解析器是**纯函数**：string 进，string 出，不依赖 HTTP / DB / 文件系统。
因此必须**先写表驱动测试，再实现功能**。必须覆盖以下边界：

- 未闭合的粗体标记、未闭合的行内代码标记、未闭合的方括号
- 行内代码内部包含星号与井号
- 代码块内部含空行
- 表格分隔行缺失
- 空输入 / 纯空白输入
- 中英文混排
- 多字节字符不被切断（用 []rune 而非 []byte）
- **链接的 `javascript:` / `data:` scheme 必须被降级为纯文本（铁律 4）**
- **链接 URL 含引号（`"`）不得逃出属性**
- **围栏代码块内含 `</code></pre><script>alert(1)</script>` 时，输出必须是转义后的纯文本，
  不得出现可执行的 `<script>`（铁律 2 + 铁律 3）**
- **行内代码（单个反引号）内含 `<script>alert(1)</script>` 时，输出必须是转义后的纯文本，
  不得出现可执行标签（铁律 1 + 铁律 3）**
- **围栏代码块语言标识含 `"`、空格、`=` 等非法字符时降级为 `class="language-text"`；
  合法标识只允许 `[a-zA-Z0-9+-]`（防属性注入，见 §9.5）**
- 标题 id 的确定性、同名去重、纯符号标题回退等（**TOC 已实现，但这些用例仍未补测试**，见第 20 章）

### 9.5 各语法的实现要点

| 语法 | 实现关键点 |
| :--- | :--- |
| **标题** | 行首 1-6 个井号，后面**必须跟空格**；h2–h4 输出 `<hN id="…">文本</hN>`，标题内**不做行内解析**（只 `html.EscapeString`）；h1/h5/h6 只输出 `<hN>` 不带 id（见第 20 章） |
| **围栏代码块** | 开闭配对；内部**跳过 Markdown 解析但内容必须 `html.EscapeString`**。**当前实现没有语言标识白名单**：直接把 `html.EscapeString(fence)` 拼进 `class="language-…"`（转义挡住了引号逃逸，但 `class="language-go foo"` 这类脏值仍会出现），白名单校验待补 |
| **引用** | 连续以 > 开头归为一块；去掉 > 后走行内解析 |
| **列表** | 连续同类型行归为一组；**一行即一项（不支持延续行）**；每项内容走行内解析 |
| **任务列表** | 列表的特殊形态；`- [ ]` 未勾选，`- [x]` 已勾选 |
| **表格** | **必须扫描到第二行（分隔行）才能确认是表格**；分隔行**必须含竖线**；支持左 / 中 / 右对齐 |
| **水平线** | 单独一行，3 个以上连字符或星号或下划线 |
| **行内代码** | 优先级最高，内部不再解析任何语法；但内容仍必须 `html.EscapeString`（只豁免 Markdown 解析，不豁免转义） |
| **图片** | **未支持**（无 `![]()` 语法，也没有 `img` 输出） |
| **链接 URL** | 只放行 `http://` / `https://` 前缀；其余（含站内相对路径与 `#` 锚点）整行降级为纯文本；URL 属性同样转义（铁律 4） |

**围栏代码块语言标识校验（防属性注入）**

语言标识会被拼进 `<code class="language-...">` 的**属性位置**，若当作普通文本直接拼接，就能闭合属性：

    开栏行：```x" onmouseover="alert(1)
    错误拼接结果：<code class="language-x" onmouseover="alert(1)">
    → 属性被闭合，事件处理器被注入 → XSS

**当前威胁状态**：本站为单作者博客，尚无评论 / 留言等访客写入口，`Render` 当前的输入只有本地文件，
**不存在外部不可信输入到达此处的通路**，因此现在没有实际 XSS 风险。仍然保留白名单校验的理由是：

- 等 `posts.content_md` 接入 `Render` 后，语言标识即成为外部输入，这条通路随之成立（信任边界前移）；
- 属性位置需要的是**合法**标识，而 `html.EscapeString` 只管**安全**、不管合法——
  `class="language-"`、`class="language-go foo"` 这类脏值它照样放行；
- 校验放在**输入侧**（开栏行解析阶段）而非渲染侧，可与转义构成两道**不共享失效模式**的防线。

规则：

- 标识只允许 `[a-zA-Z0-9+-]`（足以覆盖 `go`、`c++`、`sqlite`、`JavaScript` 等）；出现任何其它字符
  （空格、引号、`=`、`>`、`#`、中文等）则**标识整体丢弃**。
- **保留原样大小写，不做小写归一**：`Go` 与 `go` 是两种不同的 class 名，写文章时须保持统一。
- **降级策略**：标识被丢弃时（含未写语言、校验不通过两种情况），输出 `class="language-text"`，
  按纯文本处理——正文一个字都不丢，只丢元数据。
- 未写语言与标识非法**不可区分**，共用同一条降级路径（有意为之：两者对读者的语义相同）。
- 即使校验通过，写入属性时仍要 `html.EscapeString`——纵深防御，不假设白名单永远正确。

> 与铁律 2 呼应：语言标识的校验发生在「开栏行解析」阶段，同样不进入正文的行内解析。

**列表（含任务列表）契约**

- 无序前缀支持三种：`-`、`*`、`+`（前缀之后**必须有空格**，否则不是列表项）。
- 有序前缀为 `1.` 形态（数字 + 点 + 空格）。
- **一行即一项**：不支持延续行。没有列表前缀的行一律结束当前列表并另行判定，**不并入上一项**。
- **不支持嵌套**（与 §9.1 的明确排除项一致）。
- 一个列表归为**一个 block**：`lines` 与 `list` 是**等长平行数组**，`list[i]` 描述 `lines[i]` 的类型
  （`listItemPlain` / `listItemTaskOpen` / `listItemTaskDone`）。
- `ordered` 区分有序与无序；有序列表只把**起始编号**记入 `listcode`，后续项在渲染时自增，
  **不解析源码里每项的实际序号**（所以 `1. 1. 1.` 也渲染成 1、2、3）。
- 每个列表项的文本走行内解析。

**表格契约**

- 表格由**第一行（表头）+ 第二行（分隔行）**共同确认；**只看第一行不得判定为表格**。
- 分隔行**必须含竖线 `|`**。这是与「水平线」分开的唯一判据，否则不带竖线的 `---` 会被 `isHRLine` 抢先匹配，表格永远认不出来。
- 单元格按 `|` 切分；首尾竖线可省略（切分后丢弃首尾的空片段）。
- 对齐标记：`:---` 左对齐、`:---:` 居中、`---:` 右对齐；**无冒号按左对齐处理**。
- 每列对齐方式存入 `table []alignKind`，长度等于列数。
- 表头与各单元格内容走行内解析。
- **分隔行缺失时整块按段落处理**，不得报错、不得降级成奇怪的半表格。

> 复杂度提示（§9.1 已注明）：表格是标准集中唯一需要「看到第 2 行才能确认第 1 行」的语法。
> 实现时用**向前看一行（`i+1`）**即可，不必真的做整块预扫描。

## 10. 认证、会话与中间件设计

### 10.1 密码派生：PBKDF2-HMAC-SHA256

| 参数 | 取值 |
| :--- | :--- |
| 派生函数 | crypto/pbkdf2（Go 1.24+ 标准库） |
| 盐长度 | 16 字节，来自 crypto/rand |
| 迭代次数 | 600,000（OWASP 2023 推荐值） |
| 密钥长度 | 32 字节 |
| 存储方式 | password_hash / salt 以 BLOB 原始字节存库 |

> **为什么不用手写 SHA-256 迭代**：SHA-256 的设计目标就是「快」，GPU 每秒可计算数十亿次，加盐也无法阻止离线暴力破解。PBKDF2 通过 HMAC 结构 + 高迭代次数人为制造计算成本。

### 10.2 会话生命周期

```text
【登录】
POST /admin/login
  → 按 username 查 admins 表
  ├─ 查到：用该行的 salt / iterations 派生
  └─ 没查到：★ 也要用固定的假 salt / iterations 派生一次（结果丢弃）
      否则“用户不存在”会直接跳过 PBKDF2，比“密码错误”快数百毫秒，
      统一错误提示就形同虚设——用户名枚举靠的是响应时间，不是文案。
  → pbkdf2.Key(password, salt, iterations, 32, sha256.New)
  → subtle.ConstantTimeCompare(派生结果, password_hash)
  → 成功：生成 32 字节随机 token，写 sessions 表，Set-Cookie，303 → /admin
  → 失败：统一错误提示（不区分"用户不存在"与"密码错误"，防用户名枚举）

【校验】每次管理路由请求
  中间件取 Cookie → 查 sessions 表（token + expires_at）→ 校验是否过期
  → 通过：从查询结果取出 admin_id，注入 request context 后放行
  → 不通过：按中间件类型返回 303 或 401
  ★ ValidSession 必须返回 (adminID int64, ok bool)；只返回 bool 就无法完成注入。

【登出】
POST /admin/logout   ★ 路由不挂 requireAuthPage（见 §7.2）
  → 若先挂鉴权：会话过期时会 303 到 /admin/login，
    下面 MaxAge=-1 的清除逻辑根本不会执行，浏览器残留失效 Cookie
  → 若请求带 Cookie：DELETE sessions 中的 token（token 不存在也当成功，保证幂等）
  → Set-Cookie 置 MaxAge=-1（Path 必须与签发时一致，否则删不掉）
  → 303 → /admin/login

【过期会话清理】
  启动时 + 每次登录成功后各执行一次：
  DELETE FROM sessions WHERE expires_at < ?
```

### 10.3 ★ 双中间件设计（本项目的核心安全机制）

#### 为什么需要两个中间件

**问题**：fetch() 默认**自动跟随 302 重定向**。

如果认证中间件在未登录时统一返回 303 到登录页，那么当 JS 调用 DELETE 接口而会话已过期时：

```text
JS: fetch DELETE
  → 服务端 303 → /admin/login
  → fetch 自动跟随重定向，最终拿到登录页的 200 OK
  → JS 判断 response.ok === true，以为删除成功
  → 实际什么都没删！
```

**解法**：让中间件区分「谁来解读失败」——

| 中间件 | 用于 | 失败响应 | 为什么 |
| :--- | :--- | :--- | :--- |
| requireAuthPage | 页面路由 | 303 到登录页 | 调用者是人类浏览器，跳转它看得懂 |
| requireAuthAPI | 数据路由（fetch） | 401 + JSON | 调用者是 JS，只有状态码它才能读 |

#### 实现规则

- **`checkAuth`** 是两种中间件共用的校验核心：已登录时返回**带 `admin_id` 的 `*http.Request`**（用 `r.WithContext` 注入），未登录时返回 `nil`。登录态的真正产物是 `admin_id`，必须随请求传下去，**不能只返回 `bool`**。
- **context key 必须是包内自定义类型**（如 `type ctxKey int` + 常量），**禁用字符串**作 context key，否则会与其它包冲突，`go vet` 也会告警。
- **`requireAuthPage`**（页面路由）：`checkAuth` 失败时 `303` 重定向到 `/admin/login`；成功则把带 `admin_id` 的请求交给下一环。
- **`requireAuthAPI`**（数据路由）：`checkAuth` 失败时返回 `401` + JSON `{"error":"unauthorized"}`；成功同样把带 `admin_id` 的请求交给下一环。
- 两者包装后返回 `http.Handler`，接入 mux 时仍需 `http.HandlerFunc(...)` 转换（见 §5.4）。

> **关键设计**：`checkAuth` 负责共用核心与注入 `admin_id`，两个包装函数只负责「失败时怎么回答」。认证逻辑只有一份，不会出现两处实现不一致的风险。

#### 分类依据是「谁调用」，不是「返回什么」

| 路由 | 成功时返回 | 调用者 | 应使用 |
| :--- | :--- | :--- | :--- |
| GET /admin | HTML 页面 | 浏览器导航 | requireAuthPage |
| POST /admin/posts | 303 重定向 | 表单提交 | requireAuthPage |
| DELETE /admin/posts/{id} | 204 | fetch | requireAuthAPI |
| POST /admin/upload | JSON | fetch | requireAuthAPI |
| **POST /admin/preview** | **JSON `{"html": ...}`** | **fetch** | **requireAuthAPI** |

**注意最后一行**：/admin/preview 成功时返回 `{"html": "<p>…</p>"}`，前端取 `html` 字段注入预览区。它是 fetch 调用的，所以**必须用 requireAuthAPI**。

如果这里用错了 requireAuthPage，会话过期时预览区会注入一整页登录页 HTML——比删除失败还诡异。

**判断口诀**：

> 问自己：**这个请求失败时，谁来解读这个失败？**
> 是「人类的眼睛」→ requireAuthPage
> 是「JS 代码」→ requireAuthAPI

### 10.4 Cookie 安全属性

签发与清除会话 Cookie 时，必须设置以下属性：

| 属性 | 取值 | 说明 |
| :--- | :--- | :--- |
| HttpOnly | `true` | ★ 阻断 JS 读取，防 XSS 窃取会话 |
| SameSite | `Lax` | ★ 防 CSRF |
| Secure | 跟随协议 | 纯 HTTP=false；用 tailscale cert/serve 上 HTTPS 后必须 true |
| Path | `/` | **签发与删除必须一致**，否则删不掉 |
| MaxAge | `SessionTTL` | 清除时置 `-1` |

> **Secure 必须跟着协议走**：Tailscale 的 WireGuard 只加密链路，不改变应用层是否 HTTPS。
> 若浏览器以 `https://` 访问，`Secure` 必须为 true，否则会话 token 在应用层仍是明文。
>
> **为什么默认存明文、什么时候必须改**：单管理员、且只有本机能读库时，明文 token 的额外风险≈0，
> 因此默认不做哈希，保持「拿 token 直接定位会话」的简单性。**触发条件**：一旦数据库文件会被备份到
> 别处、或将来出现第二个管理员，就必须改为存 token 的 SHA-256（查询时对收到的 token 取哈希再查）。

### 10.5 CSRF 防护说明

SameSite=Lax 已覆盖主要攻击面：

跨站发起的 POST / DELETE 请求，浏览器**不会携带 Cookie**（Lax 只允许顶级导航的 GET 携带），因此跨站删除请求会因缺少 Session 而被中间件直接拦截。

单管理员系统因此**无需额外引入 CSRF Token**。

### 10.6 常量时间比较

token 与密码哈希的比对**必须使用 crypto/subtle.ConstantTimeCompare**。
普通双等号比较会在第一个不同字节处提前返回，攻击者可通过响应时间差异逐字节猜测（时序攻击）。

### 10.7 安全响应头中间件

所有响应统一追加以下响应头：

| 头 | 值 | 作用 |
| :--- | :--- | :--- |
| X-Content-Type-Options | `nosniff` | 阻止浏览器 MIME 嗅探。**对 `/uploads/` 尤其关键**，否则“合法图片头 + 尾部脚本”的多态文件可能被当成 HTML 执行 |
| X-Frame-Options | `DENY` | 防点击劫持，后台页面禁止被 iframe 嵌套 |
| Content-Security-Policy | `default-src 'self'; img-src 'self' https: data:; style-src 'self'; script-src 'self'; form-action 'self'; base-uri 'self'; frame-ancestors 'none'` | 限制资源来源；`frame-ancestors 'none'` 是 `X-Frame-Options` 的现代替代；`form-action 'self'` 防表单劫持；`base-uri 'self'` 防 `<base>` 注入；highlight.js 必须本地托管（`/static/vendor/`）才能通过 `script-src 'self'` |
| Referrer-Policy | `strict-origin-when-cross-origin` | 外链跳转不泄露完整 URL |
| Cache-Control | 仅对 `/admin` 前缀（含 `/admin/login`）响应设为 `no-store`，其余路由不设 | 登录页与后台含会话状态和表单，被浏览器或中间层缓存后，登出仍可能从缓存看到后台内容 |

> **`/admin` 前缀必须 `no-store`**：实现上在安全响应头中间件里用
> `strings.HasPrefix(r.URL.Path, "/admin")` 判断即可（`/admin/login` 天然被覆盖）。
> 宁可多覆盖（如将来若有 `/administrator` 之类路径被一起设成 `no-store`）也不能漏掉后台页面。

放在中间件链的**最外层**（最先进入、最后返回），这样认证失败的 401/303 响应也会带上这些头。

### 10.8 管理员账号初始化（Bootstrap）

系统没有注册接口，`admins` 表也不会凭空多出第一行。必须有一个**一次性**初始化入口，否则阶段三根本没法登录。

- 形态：独立命令 `cmd/admin-seed`（复用 `internal/db` + `internal/auth`，不启动 HTTP 服务，见第 3 章目录树）。
- 输入（**代码现状**）：用户名走 `-user` 标志（默认 `admin`）；密码从 **stdin 读一行**（`bufio.Reader`，空密码报错），不使用环境变量。
- 行为：username 已存在且未传 `-reset` → 报错退出，不覆盖；传 `-reset` 才更新哈希并**顺带删除该 admin 的所有 session**；不存在则插入。

> **为什么不做「首次启动自动建 admin」**：那样初始密码必须以环境变量形式长驻在容器运行时配置里。
> 一次性命令执行完即退出，凭据不在运行态驻留。

### 10.9 登录限流（含客户端 IP 的信任边界）

600,000 次 PBKDF2 每次约数百毫秒 CPU，登录接口若完全不设限，一个循环就能把边缘机 CPU 打满（DoS），
同时允许无限次密码猜测。

**限流键 = 客户端 IP，但 IP 必须取对。** 服务在 Nginx 后面，`r.RemoteAddr` 永远是代理地址
（`127.0.0.1:xxxxx`）。直接用它会出现「全球共用一个桶」——管理员自己输错 5 次就被 429 锁死，
限流退化成全局开关。反过来，无条件信任 `X-Forwarded-For` 又会被伪造头绕过。

取 IP 规则（**这是信任边界，不可省**）：

- 仅当 **TCP 对端是本机回环**（`127.0.0.1` / `::1`，即 Nginx 与本进程同机）时，才采信代理覆写写入、客户端无法伪造的 `X-Real-IP`。
- **刻意不读 `X-Forwarded-For`**：XFF 是「追加」语义，最左值由客户端自填；Nginx 用 `$proxy_add_x_forwarded_for` 会得到「伪造值, 真实IP」——取最左=取伪造值，攻击者每次换一个值即可绕过限流；即便改取最右，也只是单层代理下的权宜，且仍多一条攻击面。既然已有不可伪造的 `X-Real-IP`，就不保留任何 XFF 回退。
- 用 `net.SplitHostPort` 去掉端口；**解析失败时不 panic**，退回原始 `RemoteAddr`。

**必须补表驱动单测**（用 `net/http/httptest` 构造请求；**当前尚未编写**，`clientIP` 无任何测试）：

| RemoteAddr | 请求头 | 期望返回 | 覆盖点 |
| :--- | :--- | :--- | :--- |
| 127.0.0.1:5555 | X-Real-IP: 1.2.3.4 | 1.2.3.4 | 回环对端采信真实头 |
| 127.0.0.1:5555 | X-Forwarded-For: 9.9.9.9 | 127.0.0.1 | **伪造 XFF 不得改变分桶** |
| 127.0.0.1:5555 | XFF: 9.9.9.9 + X-Real-IP: 1.2.3.4 | 1.2.3.4 | 优先且只认 X-Real-IP |
| 203.0.113.7:5555 | X-Real-IP: 1.2.3.4 | 203.0.113.7 | 非回环对端不采信任何头 |
| 无端口字符串 | 任意 | 原值 | `SplitHostPort` 失败不 panic |

- **固定窗口失败计数**（当前实现）：`map[string]*loginBucket`（`count` + `windowStart`）+ `sync.Mutex`；
  只统计**失败**，成功登录清零；同一 IP 在 `LoginRateWindow`（60s）内失败达到 `LoginRatePerMin`（5 次）即拒绝。
  （设计早期写的是"令牌桶"，实际落地是固定窗口计数器，语义更简单：窗口到期即清零。）
- 因为计数只对**已出现失败的 IP** 建桶，陌生 IP 不会预占内存。
- **固定失败延迟未实现**：等时化只依赖 PBKDF2 本身（用户不存在时也走一次完整派生），不额外 `time.Sleep`。
- 触发限流返回 **429 Too Many Requests**，并给人类可读文案。

> 单管理员场景不引入 Redis 等外部组件，进程重启后计数清零可接受。
> **注意**：`map` 会随 IP 增长，需要惰性清理或给桶设 TTL，避免内存无界增长。
> `X-Real-IP` 由 §15.2 的 Nginx 用 `$remote_addr` 覆盖式写入，客户端无法伪造；
> 只在 TCP 对端为回环时才采信，是为了防止服务被直接暴露时上游伪造该头。
> `X-Forwarded-For` 已明确**不参与取 IP**（最左值可伪造），故 §15.2 仍保留它只为兼容其它上游，Go 侧不读。

### 10.10 请求日志与健康检查

- **请求日志中间件（未实现）**：设计为标准库 `log` 输出 方法 / 路径 / 状态码 / 耗时 / 客户端 IP，
  放在安全响应头内层；需包装 `http.ResponseWriter` 捕获状态码。当前代码只有零散 `log.Printf`
  （启动 PRAGMA 自检、handler 内部错误），没有统一访问日志。
- **`GET /healthz`（已实现）**：只证明进程活着，**不查数据库、不鉴权**，返回 `200 {"status":"ok"}`。
  不要做成查库的深度探针——那会把数据库抖动放大成整个服务探针失败。
- 不引入第三方日志库，保持标准库 `log`；需要结构化日志时后期单独评估。

## 11. 图片上传设计

> **状态：未实现（待办）**。代码中没有 `POST /admin/upload`、没有 `/uploads/` 路由、`admin.js` 中上传逻辑仍是 TODO；`./data/uploads/` 目前只存项目 ZIP 附件（见 §12）。本章保留完整设计，供后续实施时照做；实施时注意：`cfg.MaxUploadBytes` 当前是 60 MiB（为 ZIP 设定），图片上限若按 2 MB，需要**另加一个配置项**，不要复用 ZIP 的常量。

### 11.1 约束规则

| 约束项 | 规则 |
| :--- | :--- |
| 大小上限 | 单张 ≤ 2 MB（Nginx 侧 `client_max_body_size 3m` 必须 ≥ 此值，否则先被 413，见 15.2） |
| 实现方式 | **先** `r.Body = http.MaxBytesReader(w, r.Body, cfg.MaxUploadBytes)`，**再** `r.ParseMultipartForm(cfg.UploadMemoryBytes)`。顺序写反则限额不生效 |
| 内存阈值 | `UploadMemoryBytes = 1 << 20`（1MiB）；超出部分落临时文件，避免 2MB 文件常驻内存 |
| 扩展名白名单 | 仅 .jpg .jpeg .png .gif .webp |
| 内容校验 | 读取文件头 magic number 校验**真实类型**（不可只信扩展名） |
| ★ 落盘扩展名 | **由探测到的真实类型映射**（image/jpeg→.jpg 等），**绝不使用用户文件名里的扩展名** |
| 存储路径 | ./data/uploads/ |
| 文件名 | **随机哈希重命名**（crypto/rand 生成） |
| 响应头 | `/uploads/` 必须带 `X-Content-Type-Options: nosniff`（见 10.7） |
| 返回值 | JSON：{"url": "/uploads/a1b2c3d4.png"} |

**复用场景**：文章插图、项目封面图（projects.cover_image）共用同一个上传接口。

### 11.2 路径穿越（Path Traversal）防御

如果保留用户提交的原始文件名，攻击者可构造类似以下的名字：

```text
../../../../etc/crontab
```

一旦服务端未校验就直接拼接路径写入，就能覆盖系统关键文件。

**随机重命名从根源上消除了这个风险。**

### 11.3 静态文件服务

`http.FileServer` 在没有 `index.html` 的目录上会列出整个目录、枚举所有上传文件，
因此必须用 `noDirList` 包裹：**路径以 `/` 结尾（目录请求）时直接 404**，且实现须**同时判空路径**。

> ★ **`noDirList` 必须包在 `StripPrefix` 外层。** `StripPrefix` 会把 `/uploads/` 剥成空字符串，
> 若 `noDirList` 在内层，`strings.HasSuffix("", "/")` 为 false，请求被放行，`http.FileServer`
> 随后把空路径规范化为 `/` 并列出整个目录——**ADR #30 的防护实际不生效**。

正确的包裹顺序：

```text
noDirList( StripPrefix("/uploads/", FileServer) )
```

### 12.2 ★ 关键决策：不调用 GitHub API

**决策**：卡片数据 100% 来自手动填写的数据库字段，**运行时不发起任何外部 HTTP 请求**。

**曾考虑的方案**：调用 api.github.com 自动抓取 Stars、主要语言、最近推送时间。

**放弃的理由**：

| # | 问题 | 说明 |
| :--- | :--- | :--- |
| 1 | **速率限制** | 未认证时 GitHub API 限制 **60 次/小时（按 IP）**，几次页面刷新就会耗尽配额 |
| 2 | **外部依赖脆弱** | GitHub 响应慢或不可达时，博客页面会跟着卡住甚至 500 |
| 3 | **需要快照机制** | 正确做法必须在"写入时"抓取并存快照，"读取时"只读库，架构复杂度陡增 |
| 4 | **需要失败降级** | 抓取失败时不能阻塞保存，也不能覆盖旧快照 |
| 5 | **Token 安全** | 若想提高配额需引入 Personal Access Token，而它绝不能入库 / 入 git |
| 6 | **收益有限** | Stars 数对个人作品的展示价值，远低于它带来的复杂度 |

**结论**：本期不实现。若未来确有需要，作为**独立的阶段八**单独立项，并严格遵守：读时绝不调 API、显式设置 http.Client{Timeout: 5s}、校验状态码、失败保留旧快照、Token 只走环境变量。

### 12.6 技术栈标签的存储与渲染

**存储格式**：两端都带逗号，形如 `,Go,Docker,SQLite,`

**为什么两端加逗号**：这样用 LIKE 匹配 `%,Go,%` 时才不会出现「Go 误命中 Golang」这类子串误判。这是为未来可能的标签筛选预留兼容性。

**渲染时的解析（铁律）**：**必须先 `strings.Trim(s, ",")` 去掉两端逗号，再 `strings.Split`**，
逐项 trim 空格后渲染为标签。

> **陷阱**：若直接 `Split` 一个空字符串，会得到 `[""]`（长度为 1 的空元素），导致渲染出一个空标签。

### 12.7 输入校验规则

| 字段 | 校验 |
| :--- | :--- |
| title | 非空，长度 ≤ 100 |
| summary | 非空，长度 ≤ 200 |
| github_url | **必须 https://github.com/ 开头（尾斜杠不可省，见下方提示）** |
| demo_url | 为空，或以 **https://** 开头（不允许 http，避免混合内容；确有 http 需求须在此写明例外） |
| cover_image | **本期跳过**（表单不提供该字段，不做校验） |
| slug | 非空，唯一（冲突返回 409，见 8.4），仅允许小写字母、数字与连字符 |
| tech_stack | 每项去空格；空项丢弃；自动补齐两端逗号 |
| status | 只能是 active 或 archived |

> **为什么校验 github_url 前缀**：该字段最终会渲染进 a 标签的 href 属性。虽然 html/template 会对 URL 做转义，但校验前缀是防御性编程的基本功——它确保你始终知道这个链接会指向哪里。
>
> **尾斜杠是判定的一部分**：必须写成 `strings.HasPrefix(u, "https://github.com/")`。
> 少写结尾的 `/` 会让 `https://github.com.evil.com` 通过校验。

### 12.11 公开下载的设计边界（自我约束）

**决策**：项目 ZIP 附件对匿名访客公开下载，`GET /projects/{id}/download` 不挂鉴权。

**理由**：作品集的价值是"点开就能拿到源码"。加登录会把访客挡在门外，把展示能力变成内网玩具。

**威胁模型**：系统是单作者、单管理员（§1.3），唯一的上传者就是站主本人。因此风险不在"别人恶意上传"，而在**自己打包时手滑把敏感文件带进去**。防护手段是发布纪律，不是服务端扫描。

**上传前自查清单（每次打包必做）**：

1. 不打包任何以 `.` 开头的文件/目录：`.env`、`.git/`、`.github/`、`.idea/`、`.vscode/`、`.DS_Store`；
2. 不打包私钥与证书：`id_rsa*`、`*.pem`、`*.key`、tailnet / headscale 配置；
3. 不打包数据库与日志：`*.db`、`*.db-wal`、`*.sqlite`、`*.log`；
4. `unzip -l xxx.zip` 看一眼清单，确认文件都在预期目录内，没有多出来的隐藏项；
5. 确认代码里没有写死内网地址（`100.64.0.x`）、账号口令、Token。

**代码侧配套加固**（不改变"公开"前提，只保证公开的是对的东西）：

| 项 | 现状 | 目标 |
| :--- | :--- | :--- |
| 文件存在性 | 直接 `http.ServeFile`；文件缺失时会把 404 文本当成 `slug.zip` 返回 | 先 `os.Stat`，缺失渲染 404 页面 |
| 路径收敛 | `filepath.Join(UploadsDir, archive_path)` | 追加 `filepath.Base` + 随机名白名单校验，防库内脏数据穿越 |
| 下载文件名 | `slug + ".zip"` 直接拼进 `Content-Disposition` | RFC 5987 `filename*=UTF-8''<urlencoded>`，避免中文/引号破坏 header |
| 归档项目 | 与 active 一样可下载（id 可枚举） | 明确策略并写死：归档仍可下载（历史版本也是作品）／仅 active 可下载 |
| 缓存 | 未设置 | 公开静态大文件加 `Cache-Control: public, max-age=3600`，减少回源 |
| 超时 | 全局 `WriteTimeout=120s` | 60 MiB 慢速下载可能被截断；若实测失败，为下载路由单独放宽 |

> ★ **CSP 硬约束（配合 §10.7 的 `script-src 'self'` / `style-src 'self'`）**：

### 13.4 预览必须走后端（关键决策）

**不允许用前端 JS 库（如 marked.js）渲染预览。**

因为这样会同时存在**两套 Markdown 解析器**（Go 一套、JS 一套），它们对同一段文本的渲染结果必然存在差异——用户在预览区看到的效果和发布后的实际效果不一致。

**统一走后端 POST /admin/preview 是唯一保证一致性的方式。**

**额外收益**：每敲一次键你的解析器就被真实执行一次，开发期反馈回路压缩到 450ms 之内。

## 15. 部署方案

### 15.1 Dockerfile 要点

| 要点 | 说明 |
| :--- | :--- |
| 多阶段构建 | builder 阶段编译，运行阶段只拷贝二进制 |
| 基础镜像 | builder `golang:1.25-alpine`（`GOPROXY=https://goproxy.cn,direct`）；运行阶段 `alpine:3.24`，`apk add ca-certificates tzdata` |
| 非 root 运行 | 构建参数 `UID/GID=1000`，`adduser -S appuser`，`USER appuser` |
| 数据卷 | `./data` 必须挂载为 volume，否则容器重建数据丢失 |
| 卷权限 | 非 root 的 appuser 必须能写挂载目录，否则首次建库失败，见 15.1.1；镜像内已 `mkdir -p /app/data/uploads && chown -R appuser:appgroup /app` |
| 编译参数 | `CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w"` |
| 静态资源 | **无需 COPY `web/`**：模板与静态文件已用 `go:embed` 打进二进制 |
| 辅助命令 | 镜像内**只**构建 `cmd/admin-seed`；`cmd/render-backfill` 不进镜像，需要时在能访问 `./data` 卷的机器上 `go run` |

#### 15.1.1 数据卷权限 Runbook（首次部署前）

容器内以非 root 的 `appuser` 运行，而 `./data` 由宿主机挂载进来。宿主机目录属主若不对应
appuser 的 UID/GID，`db.Open` 创建 `blog.db` 时会因权限失败（`-wal` / `-shm` 同样需要写权限）。

```bash
# 宿主机执行：让挂载目录对容器 UID/GID 可写（取值与 Dockerfile 中 appuser 一致）
sudo install -d -o <UID> -g <GID> ./data ./data/uploads
```

验收：容器启动日志出现三项 PRAGMA 实际值，且 `./data/blog.db` 与 `blog.db-wal` 生成。

### 15.2 Nginx 配置要点

> **状态：当前线上未使用本节配置（部分实现）。** 实际部署链路见 §0.3：compose 只把端口绑到 Tailscale 地址 `100.64.0.1:5200`，靠"不可路由"实现内网隔离，而不是靠 Nginx 的 `allow/deny`。若将来把 5200 暴露到公网，必须补本节配置——**并且 `client_max_body_size` 至少要 `60m`**（当前值是为 2 MB 图片写的；本项目上传的是 ≤ 60 MiB 的项目 ZIP）。

```nginx
# 管理后台：仅 Tailscale 网段可访问
# ★ 必须用 ^~ /admin（不带尾斜杠）：location /admin/ 不匹配 /admin 本身，
#   /admin 会落到下面的 location / 从而绕过白名单，使 17.3 的 403 验收失败。
location ^~ /admin {
    allow 100.64.0.0/10;
    deny all;

    # ★ 默认 1m 会把 2MB 上传挡在 Nginx，Go 侧根本收不到；必须 >= Go 的 MaxUploadBytes
    client_max_body_size 3m;

    proxy_pass http://127.0.0.1:5200;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

# 公网正常访问
location / {
    client_max_body_size 1m;   # 公网只读，不需要大 body
    proxy_pass http://127.0.0.1:5200;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

| 21 | **代码块语言标识注入** | 开栏语言标识写 `x" onmouseover="alert(1)` | 当前实现会 `html.EscapeString` 后拼进 class，属性未被闭合、无事件注入；**白名单降级尚未实现（缺口）** | [ ] |
| 22 | **行内代码 XSS** | 发布含行内代码、代码内含 `<script>alert(1)</script>` 的文章 | 详情页显示转义后的纯文本，不出现可执行标签（铁律 1 + 3） | [ ] |
| 23 | **公开下载源码包（预期行为）** | 未登录直接 GET `/projects/{id}/download` | 返回 200 且拿到原始 ZIP —— **这是设计要求，不是缺口**。同时验证：无附件 / 不存在的 id 返回 404；上传前已按 §12.11 自查清单确认包内无 `.env`、`.git/`、私钥 | [ ] |

## 20. 文章目录（TOC）设计

> **状态：已实现（v2.2，2026-11-28）。** 解析器产出标题 `id` 与 `[]Heading`；`posts` 已有 `toc_html` 列
> （`user_version = 3`）；`post.html` 在卡片外输出 `<aside class="toc">`；`app.js` 的 `bindTOC()` 做折叠与高亮；
> `cmd/render-backfill` 已实现，`ParserVersion = 2`。本节描述**代码现状**，与实际实现不一致处以代码为准。
>
> **v2.0 新增，v2.2 按实现回写。** 本节是目录功能的唯一真相源。§8 / §9 / §13 / §17 中与之相关的条目只做指针，不重复规则。

### 20.1 目标与非目标

| 类别 | 内容 |
| :--- | :--- |
| **目标** | 文章详情页右侧显示层级目录；随滚动高亮当前小节；可折叠子树；**禁用 JS 时目录仍存在且可跳转** |
| **非目标** | 不做阅读进度条；不做跟随浮窗目录；不做目录内搜索；h5 / h6 不进目录 |

三条硬性取向：

1. **结构在后端，交互在前端。** 标题 `id` 与目录 HTML 由 Go 侧产出并随页面下发；JS 只负责折叠与高亮。
2. **目录是 `content_html` 的同源产物，不是第二次解析的产物。** 禁止在请求期扫描 `content_html` 反推标题。
3. **无 JS 可用。** 目录是页面结构的一部分，不是 JS 生成物。

### 20.2 职责切分（本节的核心决策）

```text
content_md
  → markdown.Render()         → (bodyHTML, []Heading)   // 一次遍历产出两份结果
  → markdown.RenderTOC(heads) → tocHTML                 // 栈建树 + 递归输出；标题 < 3 个时返回 ""
  → posts 表同事务写入 content_html / toc_html / render_version
  → 详情页模板注入两个 template.HTML（ContentHTML / TOCHTML）
  → app.js 只做两件事：折叠、高亮
```

**扁平切片是存储与传输形态，树只是渲染期的临时视图。**

```go
type Heading struct {
    Level int    // 2..4，仅该区间被收集
    Text  string // 用于显示的纯文本（不含行内标记）
    ID    string // 文档内唯一
}

func Render(src string) (body string, headings []Heading)
```

- **不存树**：不建 `toc_json` 列、不把树传进模板、不把树暴露成导出类型。
- **树的构建只有一条规则**：新标题入栈前，`while 栈顶.Level >= 当前.Level` 弹出，然后挂到新栈顶之下。跳级（h2 后直接 h4）由此被自动规范化，**不需要特判**。
- 将来要「移动端只显示两级」「默认收起」这类需求，只改渲染期这一个函数，解析器与存储都不动。**这是选扁平存储而非树的唯一理由：可逆。**

### 20.3 解析器改动

#### 20.3.1 签名变更的连带影响

`Render` 由「返回 string」变为「返回 string + `[]Heading`」，三处调用点必须同步改，漏一处编译不过（这是好事）：

| 调用点 | 处理 |
| :--- | :--- |
| 保存（`POST /admin/posts`、`POST /admin/posts/{id}`） | `Render` 后调 `RenderTOC`，两段结果分别写入 `content_html` / `toc_html`，`render_version` 同步刷新 |
| 预览（`POST /admin/preview`） | **只返回 `{"html": ...}`**，不生成也不返回 toc；理由见 20.7.5 |
| 回填（`cmd/render-backfill`） | 两列一起重算，见 20.4 |

#### 20.3.2 id 生成规则（必须确定性）

| 步骤 | 规则 |
| :--- | :--- |
| 取文本 | 标题行去掉前导 `#` 与空格后的**纯文本**。标题当前不走行内解析，文本即原文 |
| 归一 | 转小写（`unicode.ToLower`）；**保留 Unicode 字母与数字（含汉字）**；其余字符（空格、标点、全角符号、`*`、反引号）一律视为分隔符，连续分隔符折叠为一个 `-` |
| 去首尾 | 去掉首尾 `-` |
| 空值回退 | 结果为空（如纯符号标题）→ `sec-{序号}`，序号按出现顺序从 1 开始 |
| 去重 | 同一篇文章内维护 `map[string]int`；重复时追加 `-2`、`-3`…（首个**不加** `-1`） |
| 转义 | 写入属性前 `html.EscapeString`。白名单已限制字符集，这一步是纵深防御 |

★ **必须确定性**：同一份 `content_md`，无论渲染多少次、在哪台机器上，`id` 必须完全一致。否则回填一次，全站被分享出去的锚点全部失效。

★ **不要用纯序号做 id**（`sec-1`、`sec-2` …）。作者在文首插入一节，后面所有编号平移，旧链接全废。`id` 必须**由内容派生**，位置变化不影响它；序号只作为「内容派生失败」的兜底。

★ 中文标题**保留汉字**，不要强行转拼音或丢弃。`id="安装"` 在 URL 里会百分号编码，难看但可读、且与内容一一对应；丢弃汉字会退化成 `sec-7`，回到上一条的漂移问题。

#### 20.3.3 其他约束

- 只收集 **h2–h4**；h5 / h6 照常渲染，不进目录。
- 正文中的 **h1 不进目录**（页面 `<h1>` 是文章标题，由模板输出）。
- 目录条目 **少于 3 条时整块不出**：`RenderTOC` 返回空串，模板内部不渲染 `<nav>`，`aside` 为空并被 `:empty` 收起（见 20.5.2）。三行字的文章配目录只会更乱。
- 条目数不设上限，前端也不做「只显示前 N 条」的截断——长文导航是目录的本职。

#### 20.3.4 测试用例（并入 §9.4 的表驱动用例）

| # | 输入 | 期望 |
| :--- | :--- | :--- |
| 1 | `## A` → `#### D` → `## B` | 树为 `A[D]`、`B`（跳级规范化） |
| 2 | `## 安装` 出现两次 | `id="安装"` 与 `id="安装-2"` |
| 3 | 纯中文标题 | `id` 为中文且非空 |
| 4 | `## `（空标题） | 回退 `sec-N`，不 panic |
| 5 | 标题含 `**粗体**` / 反引号代码 | `id` 中不出现 `*` 与反引号 |
| 6 | 同一输入连续渲染两次 | 两次 `[]Heading` 完全相等（确定性） |
| 7 | 全篇只有 2 个标题 | `toc_html` 为空串 |
| 8 | 正文含 h1 / h5 / h6 | 均不出现在 `[]Heading` 中 |
| 9 | 标题全为标点（如 `## ---`） | 回退 `sec-N`，不与水平线语法混淆 |

### 20.4 存储与迁移

- `posts` 表新增 `toc_html TEXT NOT NULL DEFAULT ''`（见 §8.1）。

### 20.5 页面与布局

#### 20.5.1 结构

```html
<article class="article">
  <header class="article-head">…</header>
  <div class="article-body prose">{{.ContentHTML}}</div>
  <footer class="article-foot">…</footer>
</article>
<aside class="toc" aria-label="文章目录">{{if .TOCHTML}}<p class="toc-title">此页上</p><div class="toc-scroll">{{.TOCHTML}}</div>{{end}}</aside>
```
```text
main.container
├── article.article      ← 正文卡片（不再包含目录）
└── aside.toc            ← 目录卡片，position: fixed 挂到卡片右侧
```

★ **`aside` 在 `.article` 之外**，是 `main` 的直接子元素。原因：目录要「挂在卡片右侧、悬空于卡片之外」，
若放在 `.article` 内部，`position: fixed` 虽仍能脱流，但语义上目录会被当成文章内容（打印、剪藏、摘要都会带上），
且 `.article` 的边框与圆角会诱发视觉归属错误。

`TOCHTML` 为空时 `aside` **元素本身仍然输出**（内部为空），靠 CSS `:empty` 收起；模板里的 `{{if}}` 只包
`toc-title` 与 `toc-scroll`，不决定 `aside` 是否存在——否则「有目录」与「无目录」是两套 DOM 结构，样式要写两遍。

#### 20.5.2 断点与塌缩

| 条件 | 行为 |
| :--- | :--- |
| 视口 ≥ 1300px 且 `toc_html` 非空 | `aside` 以卡片形态 `position: fixed` 挂在正文右侧，`width: 230px`，**不占正文栏宽** |
| 视口 < 1300px | `aside` 隐藏（`display: none`），正文独占 |
| `aside:empty` | 不显示（与上一条共用 `display: none`），不预留任何空白 |

断点取 **1300px** 而不是 1180px：目录卡宽 230px + 与正文的 28px 间隙，若在 1180px 展开，
正文列会被压到 800px 以下，代码块开始横向滚动。1300px 是「正文仍 ≥ 960px、卡片有处可挂」的临界点。

实际定位值（`app.css`）：

```css
@media (min-width: 1300px) {
  .toc:not(:empty) {
    display: flex; flex-direction: column;
    position: fixed;
    top: 128px;                                   /* 让开 .back-fab（78px + 38px + 12px） */
    left: calc(50vw + var(--maxw) / 2 - 28px);    /* 正文卡片右缘再往右 28px */
    width: 230px;
    max-height: calc(100vh - 160px);
    max-height: calc(100dvh - 160px);             /* 移动端地址栏收起时不超屏 */
    background: var(--bg-raised);                 /* 与正文同材质，不做半透明 */
    border: 1px solid var(--border-strong);
    border-radius: var(--radius);
    box-shadow: var(--shadow-2);
  }
}
```

- **不用 `position: sticky`**。sticky 需要父元素提供纵向滚动空间，而目录是「挂在卡片外」的，
  与正文不同高；fixed 更直接，也免去「祖先 overflow 让 sticky 失效」的整类坑（见 20.7.7）。
- `left` 用 `50vw + var(--maxw)/2` 而不是写死像素：`--maxw` 是 `clamp(720px, 60vw, 960px)`，
  写死数字在宽屏或浏览器缩放后会与正文边缘错位。
- 目录内部 `.toc-scroll { overflow-y: auto; }`，滚动条 `scrollbar-width: thin`，
  **不要 `overflow: hidden` 藏起来**——长目录需要可见的滚动位置。
- `.toc-scroll` 左侧留 `padding-left: 20px`，是为了容纳悬停才浮现的折叠钮（`left: -20px`），
  同时避免负偏移把内容挤出卡片、逼出横向滚动条。

#### 20.5.3 锚点偏移（必做，否则等于没做）

`.site-nav` 是 `position: sticky; top: 0`（见 app.css），锚点跳转后标题会被导航条盖住。三行 CSS：

```css
.article-body h2, .article-body h3, .article-body h4 { scroll-margin-top: 96px; }
html { scroll-behavior: smooth; }
@media (prefers-reduced-motion: reduce) { html { scroll-behavior: auto; } }
```

这三行同时**取代**了「JS 平滑滚动」与「JS 更新 hash」：浏览器原生处理锚点跳转、`hashchange`、以及复制链接。JS 再写一遍只会与默认行为打架（重复滚动、hash 被覆盖）。

### 20.6 前端（app.js 的两项职责）

| # | 职责 | 实现要点 |
| :--- | :--- | :--- |
| 1 | **折叠子树** | 有子列表的 `li` 追加 `.has-children`；`<button class="toc-toggle" aria-expanded="true">` 放在 `<a>` **之前**；点按钮切换 `.is-collapsed`，点链接只跳转 |
| 2 | **高亮当前节** | `scroll` 事件用 `requestAnimationFrame` 合并；用 `docTop(el)` 沿 `offsetParent` 链累加得到**文档坐标**（不能直接取 `offsetTop`，其参照物是 `offsetParent`，这里是 `.article` 而非文档）；`measure()` 在初始化与 `resize` 时重算各标题 `tops`；激活「最后一个 `tops[i] <= scrollY + 96` 的标题」；`scrollY + innerHeight >= scrollHeight - 2` 时强制激活最后一条 |

约束：

- **不要用 `<details>` / `<summary>` 做折叠**：`<summary>` 里放 `<a>`，点击会「既跳转又折叠」，两种行为无法分离。
- **不要用 IntersectionObserver**：它回答的是「是否进入视口」，不是「当前读到哪一节」；要补「离开视口但仍是当前节」的状态，还要单独特判页底最后一节。线性扫几十条 `offsetTop` 成本可忽略，且**可验证**。
- 高亮同步写 `aria-current="true"`，全文档只保留一个。
- 折叠状态**不持久化**：目录是阅读辅助，不是用户配置，不写 localStorage。
- **JS 增量控制在 80 行以内。** 超出说明把 CSS 该做的事搬进了 JS（回到 20.5.3）。

### 20.7 陷阱清单

1. **跳级标题**：固定槽位数组 `levels[n]` 会丢父或 panic。用栈（20.2）。
2. **同名标题**：不去重则第二个锚点永远跳不到第一个之后。
3. **序号制 id 导致锚点漂移**：见 20.3.2 的 ★。**这是本节唯一「上线后再改代价极高」的决策**——锚点一旦被分享，id 规则就冻结了。
4. **h1 混入目录**：正文里的 h1 会排在文章标题之上，目录第一项指向页头。
5. **预览区渲染目录**：`/admin/preview` **只返回正文 `html`，不返回 toc**。预览容器是窄栏、没有侧栏布局，渲染目录只会误导；且**目录是页面陈设，不是文档内容**，这与 §13.4「预览必须走后端」不冲突——两边共用的仍然是同一个 `Render`。
6. **目录与正文不同步**：唯一可能是「改了 `content_md` 却只刷新 `content_html`」。两列必须同事务写入（§8.6）。
7. **`sticky` 被 `overflow` 废掉（历史陷阱）**：v2.2 最终采用 `position: fixed`，本坑不再作用于目录；
   但 `.article` 早期为裁剪 `overflow: hidden`，改为 fixed 后已删除该属性。若将来有人把目录改回 sticky，
   必须先确认 `.article` / `main.container` 上没有 `overflow`。
8. **CSP**：折叠与高亮的样式全部写在 `app.css`，JS 只用 `classList` / `dataset`，不拼 `style.cssText`（`style-src 'self'` 虽不拦 CSSOM，但与 §13.3「样式只在 app.css」的原则冲突）。
9. **回填顺序**：先加列再回填（20.4）。
10. **把目录塞进 `content_html`**：目录会出现在每个 RSS / 摘要 / 剪藏的正文里，且无法单独布局。**必须是独立列。**

| 39 | 登出鉴权 | 挂 `requireAuthPage` | **不挂鉴权，直接清 Cookie** | 会话已过期时会先 303 到登录页，`MaxAge=-1` 清除逻辑不执行，失效 Cookie 残留 |
| 40 | 后台缓存策略 | 默认缓存 | **`/admin` 前缀响应 `Cache-Control: no-store`** | 登录页与后台含会话状态，缓存后登出仍可能从缓存看到后台内容 |
| 41 | CSP 与内联交互 | 允许内联 / 加 `unsafe-inline` | **模板禁内联事件、内联 `<script>`、内联 `style=`，admin.js 用 `addEventListener`** | `script-src 'self'` 会拦截内联；为修 bug 加 `unsafe-inline` 等于废除这条 XSS 防线 |
| 42 | 进程退出 | 直接 `ListenAndServe`（收到 SIGTERM 即被硬杀） | **`signal.NotifyContext` + `srv.Shutdown(10s)`** | 不处理会直接切断在途请求；Docker `stop` 发的是 SIGTERM，必须监听 |
| 43 | 目录 HTML 的产出层 | 前端扫 DOM / JS 生成 id；请求期扫 `content_html` 反推标题 | **解析器同源产出 `[]Heading`，渲染成 `toc_html` 列** | 单一真相；不引入第二套 HTML/Markdown 解析；无 JS 仍可跳转 |
| 44 | 目录数据结构 | 解析器直接产出树，或落库为 `toc_json` | **扁平 `[]Heading` 存储，渲染期用栈临时建树** | 扁平可推出树、树推不回扁平；折叠/分级需求只改渲染期一个函数，解析器与存储不动 |
| 45 | 标题 id 规则 | 纯序号（`sec-1`）/ 拼音 / 纯 ASCII | **由内容派生，保留 Unicode 字母与数字（含汉字），序号仅作空值回退** | 序号随插入位置整体平移，会让已分享的锚点全部失效；id 一旦外链即冻结 |
| 46 | 目录折叠控件 | `<details>` / `<summary>` | **JS 切换 `<button>` 上的 `.is-collapsed`** | `<summary>` 内嵌链接会「点击既跳转又折叠」；且高亮本就需要 JS，`<details>` 换不来无 JS 收益 |
